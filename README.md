# Metashape MCP

[English overview](README.en.md) · [MIT License](LICENSE) · [Security](SECURITY.md)

Локальный MCP-сервер версии 0.46.0 со 122 инструментами, 5 статическими ресурсами, 8 resource templates и 6 консервативными prompt-шаблонами для Agisoft Metashape Professional. Он управляет проектами и исходными фотографиями, опорными данными, EXIF/XMP, системами координат, калибровкой сенсоров и измерениями фигур, построением, безопасной очисткой облаков точек, экспортом и проверяемым реимпортом моделей. Проверен на macOS с Metashape Professional 2.2.0. Внешний процесс использует официальный Python SDK MCP. Обращения к Metashape выполняются в основном потоке приложения.

Культурное наследие, археология, музейные предметы, исторические здания и мониторинг их изменений — приоритетный профиль проекта: для них особенно важны неизменность исходников, происхождение данных, доказуемые масштаб и координаты, обратимость и воспроизводимый отчёт. Ядро при этом остаётся универсальным для предметной, наземной, воздушной и геодезической фотограмметрии.

## Установка, запуск и подключение

1. Скопируйте всю папку MCP в постоянное место. Не смешивайте файлы разных версий: для обновления готовьте новую папку целиком. На macOS при ручной упаковке с сетевого тома исключайте служебные `._*` файлы (`COPYFILE_DISABLE=1` для `tar`). Они не входят в Git и серверу не нужны.
2. Установите `uv`, если его ещё нет. Других глобальных Python-пакетов MCP не требует: `uv` создаёт изолированные окружения по PEP 723-зависимостям скриптов.
3. В Metashape выберите **Инструменты → Запустить скрипт** и откройте `start_metashape_mcp.py` из этой папки. При первом запуске `uv` загружает MCP SDK в отдельный кэш.
4. В MCP-клиенте выберите транспорт **Streamable HTTP** и адрес `http://127.0.0.1:8766/mcp`. Чтобы использовать другой порт, задайте `METASHAPE_MCP_URL` до запуска Metashape.
5. Для вызовов инструментов укажите HTTP-заголовок `Authorization: Bearer <токен>`. На macOS токен находится в `~/Library/Application Support/Metashape MCP/server/8766/access-token`. На других системах каталог определяется через Qt GenericDataLocation. Файл создаётся с правами только владельца (`0600`). Каталог инструментов и проверка подключения доступны без токена, вызовы инструментов — нет.
6. В окне состояния добавьте одну или несколько разрешённых рабочих папок. Кнопка «Разрешить <папка>» одним нажатием добавляет папку открытого проекта Metashape (или папку MCP, если проект не сохранён); «Добавить папку…» открывает выбор сразу в ней. Открытие и создание проектов, добавление фотографий, экспорт и изменения проекта через MCP блокируются за их пределами.

Повторный запуск скрипта в том же экземпляре Metashape показывает окно состояния и безопасно перезагружает сервер. Сервер работает до выхода из Metashape. Окно можно закрыть отдельно.

## Обновление и удаление

- Для обновления завершите активные задания, распакуйте новую версию в отдельную папку и запустите её `start_metashape_mcp.py`. Вспомогательные модули явно выгружаются по именам, поэтому перенос между папками не смешивает старый и новый host-код. После появления статуса «На связи» старую папку можно архивировать.
- Кнопка «Перезагрузить сервис» перечитывает текущую папку. Команда `reload_service` доступна только при включённой предупреждающей галке разработчика и не работает во время задания.
- Для удаления закройте Metashape и уберите папку MCP. Пользовательские настройки, токен, журналы и точки восстановления намеренно остаются в системном каталоге `Metashape MCP`, чтобы удаление кода не уничтожало возможность отката. Удаляйте этот каталог отдельно только если больше не нужны настройки, журналы, карантины и восстановление.
- Никогда не удаляйте рядом с проектом `.metashape-mcp-quarantine`, пока не уверены, что откат больше не потребуется.

## Быстрая диагностика

- Окно может кратко показать «Нет подключения» во время первого создания окружения; затем должно появиться `metashape-mcp <версия> · MCP <протокол>`. Кнопка «Проверить сейчас» повторяет проверку.
- `preflight()` должен вернуть `ok=true`, отсутствие активного задания, доступные разрешённые корни и достаточное место. `get_service_log` читает постоянный журнал MCP, `get_metashape_log` — консоль Metashape.
- `Address already in use` означает занятый порт: остановите другой экземпляр или заранее выберите другой локальный порт. Сервер резервирует порт до создания токена и журнала.
- «Файл проекта не найден», read-only, несохранённый проект, отсутствующий разрешённый корень и нехватка места блокируются до основной операции. Не обходите эти проверки расширением разрешённого корня на весь домашний каталог.
- Без токена и с неверным токеном инструменты возвращают `Требуется локальный токен Metashape MCP`. Не передавайте токен удалённым сервисам и не публикуйте его в конфигурации репозитория.

## Ресурсы и готовые сценарии

Статические ресурсы читают живое состояние, но ничего не изменяют: `metashape://service/status`, `metashape://project/summary`, `metashape://project/chunks` (до 100 чанков; дальше — `list_chunks`), `metashape://capabilities/safe-workflows` и бинарный PNG текущего окна `metashape://viewport/current`. Как и рабочие инструменты, они требуют локальный bearer-токен.

Resource templates `metashape://chunk/{chunk_key}/…` дают сводку чанка, камеры, сенсоры, tie points, облака, модели, DEM и ортомозаики. Точный числовой ключ безопаснее изменяемого названия чанка.

Шесть prompt-шаблонов охватывают предметную съёмку, аэросъёмку, ГИС/карьер, диагностику выравнивания, пакетный экспорт и подбор качества. Они сами не запускают обработку. Каждый шаблон начинает с чтения проекта, запрещает угадывать CRS/единицы/пороги, сохраняет цепочку `prepare → start → wait → проверка → accept/reject` и не предлагает `run_user_script` без отдельного разрешения пользователя и настроек интерфейса.

## Инструменты

| Вызов | Что возвращает |
| --- | --- |
| `get_service_status` | Версия и PID запущенной Metashape, идентификатор запуска сервера. Для проверенной версии указана ссылка на справочник API. |
| `get_project_summary` | Состояние документа, имя файла, число чанков, ключ и имя активного чанка, число его камер и маркеров. |
| `get_alignment_diagnostics(chunk_key)` | Выравнивание, пространственный охват и шаги камер, относительные разрывы, серии невыровненных камер и ошибки GCP/check points. Разрыв больше трёх медианных шагов — только относительный индикатор, не универсальный порог дрейфа. |
| `get_elevation_statistics(chunk_key, elevation_key)` | Размер, разрешение, границы, min/max высоты, площадь покрытия и CRS точной или активной DEM. |
| `compare_elevations(chunk_a_key, chunk_b_key, …)` | Только чтение: статистика `B − A` по регулярной выборке общей области двух DEM с одинаковой CRS. Не выдаёт выборку за объём. |
| `preflight()` | Готовность Metashape и проекта, проблемы и предупреждения, активное задание, число точек восстановления, свободное место и доступность каталога сервиса. |
| `create_project(path)` | Создаёт и открывает новый проект `.psx` или `.psz`. Требует абсолютный путь, не перезаписывает существующие данные и не закрывает проект с несохранёнными изменениями. |
| `open_project(path)` | Открывает существующий проект. Не закрывает текущий проект с несохранёнными изменениями. |
| `save_project()` | Сохраняет текущий проект по его существующему пути. |
| `save_project_as(path)` | Сохраняет проект под новым именем и делает новый файл активным. Существующий проект не перезаписывается. |
| `add_chunk(label)` | Создаёт именованный чанк и делает его активным. |
| `add_photos(chunk_key, paths)` | Добавляет в чанк фотографии по абсолютным путям. До изменения проекта проверяет наличие файлов и повторы. |
| `list_chunks(offset, limit)` | Ключ, название, состояние и число камер каждого чанка. Поле `active_chunk_key` указывает активный чанк. |
| `list_cameras(chunk_key, offset, limit)` | Камеры текущего кадра, включая отключённые. Для каждой указаны ключ, название, тип и состояние. Для обычных камер поле `aligned` показывает наличие рассчитанного положения. |
| `list_chunk_assets(chunk_key)` | Наличие связующих точек, списки наборов карт глубины, облаков точек, моделей, тайловых моделей, ЦМР и ортомозаик в текущем кадре. Для каждого результата указаны ключ, название и выбор по умолчанию, для моделей также число текстур. |
| `set_active_chunk(chunk_key)` | Делает чанк активным, возвращает предыдущий активный. |
| `duplicate_chunk(chunk_key, label, items, keypoints)` | Копия чанка с камерами и маркерами плюс только перечисленные данные (`tie_points`, `depth_maps`, `point_clouds`, `models`, `tiled_models`, `elevations`, `orthomosaics`, `masks`); точка восстановления. Metashape делает копию активной. |
| `set_chunk_enabled(chunk_key, enabled)` | Архив без удаления: чанк выключается (`enabled=false`) и остаётся в проекте со всеми данными; точка восстановления. |
| `remove_chunk(chunk_key, confirm_label)` | Удаляет чанк из проекта `.psx` и сохраняет. `confirm_label` должен совпадать с именем чанка. Папка данных чанка сначала переносится в `.metashape-mcp-quarantine` рядом с проектом (тот же диск — мгновенно, без копирования); `restore_point` возвращает и чанк, и данные. Metashape при собственном удалении стирает только часть данных (связующие точки), остальное остаётся мусором. |
| `accept_job_result(job_id, source_action, confirm_source_label)` | Оставить результат задания на копии: копия получает имя исходного чанка и становится активной; исходный — в архив (`archive`, по умолчанию: выключен, имя «… · архив») или удаляется в карантин (`remove`, нужно `confirm_source_label`). Сохраняет проект после точки восстановления. |
| `reject_job_result(job_id)` | Отказаться от результата: рабочая копия задания удаляется в карантин (только если у неё всё ещё имя задания). Исходный чанк не трогается. |
| _Место на диске_ | План каждого задания на копии содержит `copy_estimate`: сколько байт займёт копия (данные, которые она берёт, плюс связующие точки и миниатюры — Metashape копирует их всегда), сколько свободно и сколько нужно (1,5× копии + 2 ГБ). При нехватке задание отказывает до копирования. |
| _Работа на месте_ | `prepare_point_cloud(..., in_place=true)` строит облако в исходном чанке без копии. Разрешено только там, где проба показала полный откат после сохранения. Классификация земли, доработка модели и автопилот — только на копии: после сохранения Metashape стирает или перезаписывает прежнюю версию данных, и откат её не вернёт. |
| `get_chunk_compatibility(chunk_keys)` | Только чтение: первый чанк — опорный; для остальных — возможны ли методы Align Chunks по точкам, маркерам (≥3 общих по имени с проекциями) и камерам (≥3 общих выровненных), совпадение систем координат, данные чанков. |
| `prepare_chunk_alignment(reference_chunk_key, chunk_keys, method, …)` / `start_chunk_alignment(job_id)` | Фоновое задание Align Chunks в открытом проекте после точки восстановления; меняется только положение `chunk_keys`. Для `markers` общие маркеры подбираются автоматически. Результат: величина изменения матрицы и масштаб каждого чанка. |
| `prepare_chunk_merge(chunk_keys, copy_*, merge_markers, merge_tiepoints, merge_assets)` / `start_chunk_merge(job_id)` | Фоновое объединение явно перечисленных (≥2) чанков в новый чанк после точки восстановления; исходные не меняются. |
| _Маски в заданиях_ | С 0.25 рабочая копия любого задания включает маски (раньше `Chunk.copy` без `MasksData` их терял). `prepare_camera_alignment` принимает `filter_mask` и `mask_tiepoints`; план показывает `cameras_with_masks`. `restore_point` возвращает `changed_files_not_restored` — изменённые на месте файлы, которые лёгкая точка восстановления не вернула. |
| `get_model_statistics(chunk_key, model_key)` | Только чтение: грани, вершины, текстуры, площадь, связные фрагменты, открытые края и ошибки топологии; объём — только для замкнутой поверхности; масштаб чанка. |
| `prepare_model_finishing(chunk_key, steps)` / `start_model_finishing(job_id)` | Доработка активной модели на копии чанка, шаги по порядку: `remove_components {min_faces}`, `fix_topology`, `close_holes {level %}`, `smooth {strength, fix_borders, preserve_edges}`, `decimate {face_count}`, `remove_low_confidence {max_percent}`, `remove_box`/`crop_box {min, max}`. Результат — цифры после каждого шага (для сглаживания — смещение вершин). Предупреждения: закрытие отверстий — экстраполяция; изменение геометрии делает текстуру недействительной, текстурируйте после. |
| `export_model(chunk_key, directory, format, …)` | OBJ, PLY, STL, FBX, GLB активной модели или по `model_key` в новую папку внутри разрешённой; текстура — только если есть (GLB встраивает). Всегда создаёт `model-coordinate-manifest.json` с CRS, transform, shift, осями, пространственными границами и SHA-256. Для последующего реимпорта нужен `clip_to_boundary=false` и экспорт без `epsg`. |
| `prepare_model_import(chunk_key, path, …)` / `start_model_import(job_id)` | Проверяемый реимпорт OBJ/PLY/STL/FBX/GLB, ранее созданного `export_model`: сверяет проект, точный ключ чанка, CRS, transform, манифест и хеш файла; импортирует только на рабочую копию, проверяет центр/масштаб/оси и при необходимости переносит текстуру исходной модели. UV сохраняется, когда формат её возвращает; для STL строится новая. Все пять форматов и изменённый OBJ после Blender 5.2 приняты на живой модели. Несовпадение блокирует приёмку. |
| `export_point_cloud(chunk_key, directory, format, …)` | LAS, LAZ, E57, PLY одного облака (активного или `point_cloud_key`), при желании только выбранные классы. |
| `export_tiled_model(chunk_key, directory, format, …)` | Точная или активная тайловая модель в Cesium 3D Tiles (`.3tz`), SLPK или OSGB. Для Cesium: 1.0/1.1, сжатие сетки, tileset transform, screen-space error и глубина каталогов. SLPK без привязанной EPSG-CRS отклоняется до экспорта; в месте назначения требуется не менее 1 ГБ свободно. Вывод идёт в новую зарегистрированную папку и при откате уходит в карантин. |
| `export_cameras(chunk_key, directory, format, save_points, save_markers, save_images)` | XML, COLMAP (`sparse/0/…`, снимки — только при `save_images`), Bundler, OPK, NVM, FBX. Для COLMAP в 2.2 — предупреждение о порядке p1/p2. |
| `export_report(chunk_key, directory, title, description, include_system_info)` | Штатный PDF-отчёт Metashape. |
| `get_reference_error_statistics(chunk_key)` | Ошибки опорных точек (GCP) и **отдельно контрольных** (координаты есть, опорные данные выключены — независимая оценка точности), число проекций каждой точки, предупреждение при < 3 опорных. |
| `set_check_points(chunk_key, marker_keys, check)` | Перевод маркеров в контрольные точки и обратно, пересчёт привязки; точка восстановления. |
| `prepare_ground_classification(…)` / `start_ground_classification(job_id)` | Классификация точек земли плотного облака на копии чанка; результат — число точек по классам до и после. Параметры по умолчанию Metashape рассчитаны на аэросъёмку (ячейка 50 м). |
| `prepare_raster_products(…, classes)` | ЦМР только по выбранным классам (например `[2]` — земля). |
| `prepare_contours(chunk_key, directory, interval, …, format)` / `start_contours(job_id)` | Горизонтали по активной ЦМР на копии и экспорт в SHP/DXF (GeoJSON/KML — только при географической системе координат). |
| `export_shapes(…)`, `prepare_shapes_import(…)` / `import_shapes(preview_id)` | Экспорт и импорт ГИС-фигур (SHP с сопутствующими файлами, DXF, GeoJSON, KML); импорт не заменяет существующие фигуры, точка восстановления. |
| `get_region`, `set_region`, `reset_region` | Область обработки: просмотр, изменение центра/размера/поворота, сброс к умолчанию Metashape; изменения с точкой восстановления. |
| `add_marker_projections(chunk_key, label, projections)` | Маркер по пиксельным координатам на выровненных снимках (≥2), с ошибкой репроекции на каждом снимке; точка восстановления. |
| `compare_chunk_markers(reference_chunk_key, chunk_key, labels)` | Только чтение: расхождение одноимённых маркеров двух чанков в общих координатах — независимая проверка выравнивания чанков. |
| `prepare_autopilot(chunk_key, steps)` / `start_autopilot(job_id)` | Цепочка задач Metashape (`[{"task": "MatchPhotos", "parameters": {"downscale": 2}}, …]`) на копии чанка: проверка имён и типов параметров, проверки между шагами, остановка на первой ошибке, отмена между шагами, уведомление macOS. Импорт/экспорт/сохранение в цепочке не разрешены. |
| `describe_autopilot_tasks(task)` | Только чтение: какие задачи принимает автопилот (27), что каждая берёт и строит, все параметры с типом и значением Metashape по умолчанию; для перечислений — допустимые значения. Перечисления задаются строкой (`"face_count": "LowFaceCount"`). Одна задача = один шаг, так что цепочка из одного шага запускает любую задачу отдельно. |

Пока Metashape выполняет запрос, другие запросы (кроме статуса и журналов) получают отказ «Metashape ещё выполняет …»: во время долгих операций Metashape обрабатывает события, и без этого запрос мог бы выполниться посреди чужой операции. Операции управления проектом недоступны во время выполняющегося задания. `create_project`, `open_project` и `save_project_as` принимают только абсолютные пути внутри разрешённых рабочих папок. То же ограничение действует для фотографий, экспорта и изменяющих операций в текущем проекте; символьные ссылки разрешаются до проверки. Перед переключением проекта сервер проверяет флаг несохранённых изменений Metashape. `save_project_as` соответствует команде «Сохранить как» и меняет активный путь проекта.

## Журналы и диагностика

Сервер раз в секунду переносит новые строки фактической консоли Metashape в постоянный `service.jsonl`. Каждая строка получает время, `run_id` и источник. Если сообщение возникло во время этапа задания, в записи также присутствуют `job_id` и имя операции. Поэтому журнал конкретного задания можно получить через `get_service_log(job_id=...)` вместе с сообщениями алгоритмов Metashape.

События `metashape_console` сохраняются после закрытия Metashape и доступны при следующем запуске сервера. `get_metashape_log` остаётся быстрым способом посмотреть текущий буфер открытой программы, а `get_service_log` используется для постоянной истории и разбора ошибок без скриншотов. Очень длинная строка ограничивается последними 32 КиБ и получает `truncated=true`.

## Точки восстановления

Перед командами, изменяющими проект, сервер автоматически создаёт точку `before:<операция>`. Для проектов `.psx` сохраняются только сам управляющий файл и `project.zip`, `chunk.zip`, `frame.zip`. Уже созданные Metashape карты глубины, облака, модели и другие тяжёлые данные не копируются. Для монолитного `.psz` необходим полный архив.

`restore_point` сначала создаёт страховочную точку текущего состояния, перемещает зарегистрированные внешние результаты в карантин, переключает Metashape на временный проект, возвращает сохранённые метаданные и заново открывает исходный путь. Если целевой `.psx` заблокирован другим или аварийно завершённым экземпляром Metashape, операция останавливается до изменения файлов и сообщает путь `lock`.

Внешние каталоги экспорта, созданные MCP, регистрируются в точке и при откате перемещаются в соседний `.metashape-mcp-quarantine/<restore_point_id>`, а не удаляются. Их можно вернуть через `restore_quarantined_output`; занятый исходный путь никогда не перезаписывается. Не зарегистрированные данные и внутренние дополнительные каталоги Metashape остаются на месте, чтобы откат не мог уничтожить результат.

## Оценка резкости

Получите ключ активного чанка из `get_project_summary`. Вызовите `prepare_image_quality` с этим ключом и проверьте имя проекта, чанк и количество снимков. Для запуска передайте выданный ID в `start_image_quality`. Статус и оценки доступны по тому же ID после отключения клиента. Одновременно выполняется одно задание.

Metashape читает каждый исходный файл и оценивает резкость полного изображения штатной функцией `Utils.estimateImageQuality`. Оценки сохраняются в базе сервиса рядом с журналом. Если файл недоступен, результаты содержат ошибку для этой камеры. После перезапуска сервера у прерванного задания сохраняются рассчитанные оценки и статус `interrupted`. [Справочник Python API Metashape 2.2.0](https://www.agisoft.com/pdf/metashape_python_api_2_2_0.pdf#page=306)

## Выравнивание камер

Передайте ключ чанка из `get_project_summary` в `prepare_camera_alignment`. План охватывает включённые фотокамеры текущего кадра. По умолчанию используются `downscale=1`, лимит ключевых точек 40 000 и лимит связующих точек 4 000. В плане видны параметры обоих этапов. Проверьте их перед вызовом `start_camera_alignment` с полученным ID.

Сервер повторно проверяет исходный чанк и список снимков, создаёт именованную копию, заново сопоставляет снимки и выравнивает камеры. Ключ копии записывается до сопоставления. Этапы и их итоги доступны через `get_service_log` с ID задания даже после переподключения клиента. Остановка во время сопоставления вступает в силу перед выравниванием. Копия находится в открытом проекте. Для записи результата на диск используйте команду сохранения Metashape. [Справочник Agisoft, методы Chunk](https://www.agisoft.com/pdf/metashape_python_api_2_2_0.pdf#page=34)

## Построение модели

Передайте ключ выровненного чанка в `prepare_reconstruction`, затем ID плана в `start_reconstruction`. В `get_job_status` доступны этап, ключ копии и рассчитанные результаты в `assets`. Журнал доступен через `get_service_log(job_id)`. Отмена вступает в силу на границе этапов. Чтобы записать результат на диск, сохраните проект в Metashape. [Методы buildDepthMaps и buildModel](https://www.agisoft.com/pdf/metashape_python_api_2_2_0.pdf#page=39)

## Масштаб и оптимизация камер

Сначала проверьте маркеры через `list_markers`. Для создания ограничения передайте ключи двух маркеров, измеренное расстояние и точность в `create_scalebar`. Значения задаются в метрах. Инструмент меняет открытый проект, но не сохраняет его автоматически.

После установки ограничений вызовите `prepare_camera_optimization` и проверьте параметры плана. `start_camera_optimization` создаёт отдельный чанк со связующими точками и выполняет штатный `Chunk.optimizeCameras`. Исходный чанк остаётся без изменений. Стадии `copy` и `optimize` записываются в постоянный журнал. Для записи результата на диск вызовите `save_project`. [Методы addScalebar и optimizeCameras](https://www.agisoft.com/pdf/metashape_python_api_2_2_0.pdf#page=34)

## Геопривязка, ЦМР и ортомозаика

Перед обработкой проверьте `get_reference_summary` и при необходимости сами значения через `list_camera_references`. `set_chunk_coordinate_system` только назначает смысл уже записанным числам и не преобразует их; поэтому EPSG следует задавать лишь когда известна исходная система опорных координат.

Для настоящего перевода значений используйте `prepare_reference_crs_transform` → `start_reference_crs_transform`. Исходный и целевой EPSG обязательны и сверяются с фактической CRS опорных данных; работа идёт на копии, которую затем нужно принять или отклонить. В проверке WGS 84 → UTM 37N результат Metashape совпал с независимым pyproj до 5 нм, при этом 57/57 выровненных камер, 21 449 связующих точек и RMS 1,645736 px сохранились. Это горизонтальная приёмка: высоты исходного набора равны нулю.

`list_geoids` безопасно читает зарегистрированные сетки. Добавление произвольного геоида пока намеренно не открыто: API 2.2.1 документирует `addGeoid`/`listGeoids`, но не документирует обратимое удаление, поэтому такая команда нарушила бы требование полного отката.

`prepare_raster_products` выбирает плотное облако как источник высот, а при его отсутствии — связующие точки. После проверки плана `start_raster_products` создаёт отдельный чанк, строит ЦМР, затем ортомозаику по ЦМР и экспортирует оба результата в GeoTIFF. Все стадии и консоль Metashape сохраняются в журнале задания. Папка экспорта регистрируется в точке восстановления и при откате перемещается в карантин. Для локальной системы координат GeoTIFF сохраняет локальную привязку, но не получает глобального географического положения. [Методы buildDem, buildOrthomosaic и exportRaster](https://www.agisoft.com/pdf/metashape_python_api_2_2_0.pdf#page=34)

## Импорт опорных данных

Сначала вызовите `preview_reference_import`. Первая версия безопасного парсера поддерживает CSV/TXT с простыми кодами столбцов `noxyzXYZabcABC` без групп `[]` и `|`. Для камер `n` должен совпадать с именем исходного файла вместе с расширением, например `IMG_001.jpg`; это фактическое правило сопоставления Metashape 2.2. Для маркеров используется их отображаемая метка.

Импорт камер и маркеров разделён параметром `items`. `create_markers=true` разрешён только для `items="markers"`. `import_reference` повторно проверяет размер, время изменения и SHA-256 файла и отказывается работать, если после preview изменился хотя бы один из них. Недопустимые числовые строки и повторяющиеся метки блокируют импорт. Не найденные метки показываются в preview, но могут быть допустимы при импорте маркеров с созданием отсутствующих записей.

`prepare_marker_detection` и `start_marker_detection` предназначены для кодированных круглых мишеней Metashape. Обнаружение выполняется на отдельной копии чанка по схеме `copy -> detect`; существующие маркеры исходного чанка не объединяются и не изменяются. При `filter_mask=true` содержимое масок входит в отпечаток плана, поэтому изменение маски потребует нового задания. Уточнение проекций также разделено на `prepare_marker_refinement` и `start_marker_refinement`, работает только по явно указанным ключам и выполняется по схеме `copy -> refine`.

## Экспорт тайловых моделей

`export_tiled_model` выбирает один точный ресурс по `tiled_model_key` либо активную тайловую модель. Выходной путь всегда новый: Metashape не может перезаписать существующий файл и не откроет модальное окно «Повторить?». Каталог регистрируется в точке восстановления, а откат перемещает его в `.metashape-mcp-quarantine`, не удаляя.

Живая проверка: Cesium 3D Tiles 1.1 — 8,4 МБ, 809 элементов (`tileset.json`, GLB-тайлы, HTML-просмотрщик); OSGB — 7,49 МБ, 212 элементов с `metadata.xml`. Оба каталога штатно ушли в карантин; рабочие копии чанка отклонены.

## Измерения фигур

`get_shape_measurements` не меняет фигуры и проект. Для линий и полигонов он читает штатные измерения Metashape, а каждую ошибку отдельно возвращает в `measurement_errors`, не теряя остальные фигуры. Для `area_on_dem`, `perimeter_on_dem` и `volume_on_dem` нужна активная ЦМР; 3D-метрики возвращаются только для действительно трёхмерной геометрии.

Единицы выводятся как метры/м²/м³ только при наличии подтверждённого масштаба чанка. Без него ответ явно помечает значения как `chunk_units`. Живая проверка: 49 горизонталей без ошибок и временный квадрат 1×1 с периметром 4 и площадью 1.
